Un texte n’est pas directement un tableau de nombres. Pour apprendre à partir de messages, il faut d’abord décider ce que chaque nombre représente. Cette décision conserve certaines informations et en efface d’autres.

Nous allons suivre le chemin du TP : textes de 20 Newsgroups, classification en sept familles, puis comparaison de mots par leurs contextes. Les exemples interactifs ci-dessous utilisent de petits corpus inventés pour rendre les calculs visibles.

1. Du texte au sac de mots

Imaginons le message « car engine car ». Déplace le curseur pour lire les unités une à une. Chaque occurrence rejoint une colonne commune : la colonne indique combien de fois le mot apparaît.

UN MESSAGE DEVIENT UN VECTEUR DE COMPTES

carenginespace

La position d’un mot est fixée par le vocabulaire, pas par sa position dans la phrase. « car engine car » et « car car engine » ont donc le même vecteur. Le modèle voit les comptes, mais perd l’ordre et une partie du sens.

Un vecteur one-hot représente une seule unité avec un seul 1 ; un sac de mots de comptes additionne les occurrences de tous les mots d’un document. Le titre du TP mentionne le premier, mais sa consigne demande bien le second.

Le pipeline du notebook

Le notebook regroupe les catégories par préfixe : comp, rec, sci, talk, soc, misc et alt. Mais ce regroupement diffère du regroupement par thèmes suggéré par la fiche du jeu de données : informatique, loisirs, sciences, vente, politique, religion et la classe None. En particulier, la religion rassemble talk.religion.misc, alt.atheism et soc.religion.christian, tandis que la politique regroupe les trois catégories talk.politics. Le dropna() du notebook retire les lignes à étiquette manquante : vérifier le traitement de None avant le rendu. Le corps des messages est tokenisé avec spaCy, puis converti en dictionnaires de comptes.

tokens = nlp.make_doc(texte)
comptes = Counter(t.text.lower() for t in tokens)
X_train = vectorizer.fit_transform(comptes_train)
X_test = vectorizer.transform(comptes_test)

Pourquoi deux méthodes ? fit_transform apprend les colonnes sur l’entraînement. transform réutilise ces colonnes sur le test : les mots inconnus sont ignorés. Une matrice sparse stocke surtout les valeurs non nulles.

2. Faire voter les mots

Le classifieur bayésien naïf apprend quels mots sont fréquents dans chaque classe. Pour un nouveau texte, il combine la fréquence préalable de chaque classe avec les indices apportés par les mots. Ajoute des occurrences de « car » et observe les scores.

EXEMPLE JOUET · DEUX CLASSES, DEUX MOTS

Exemple : P(car|auto)=0,8 ; P(space|auto)=0,2 ; P(car|science)=0,2 ; P(space|science)=0,8. Classes a priori égales.
score(c) = log P(c) + Σmot compte(mot) · log P(mot | c)

La classe au score le plus élevé est prédite. Le modèle dit « naïf » suppose les mots indépendants conditionnellement à la classe. Les logarithmes transforment le produit de petites probabilités en somme et évitent les problèmes numériques.

Le lissage ajoute une petite masse aux comptes. Sans lui, un mot jamais observé dans une classe donnerait une probabilité nulle à toute la combinaison. Dans MultinomialNB, alpha=1 par défaut.

model = MultinomialNB(alpha=1)
model.fit(X_train, train["label"])
y_pred = model.predict(X_test)
# class_log_prior_ : probabilités a priori en log
# feature_log_prob_ : log P(mot | classe)

3. Une bonne prédiction, pour qui ?

Pour une classe donnée, la précision demande : parmi les documents prédits dans cette classe, combien y sont vraiment ? Le rappel demande : parmi ceux qui y appartiennent vraiment, combien ont été retrouvés ? Modifie les cases pour voir les deux regards.

MATRICE POUR UNE CLASSE · EXEMPLE BINAIRE

Précision · VP/(VP+FP)
Rappel · VP/(VP+FN)
F1 · 2PR/(P+R)

La moyenne macro calcule la métrique pour chaque classe puis leur donne le même poids, même si les effectifs diffèrent. Dans une matrice de confusion scikit-learn, les lignes sont les vraies classes et les colonnes les classes prédites. normalize="true" normalise chaque ligne.

precision_score(y_true, y_pred, average="macro")
recall_score(y_true, y_pred, average="macro")
f1_score(y_true, y_pred, average="macro")

4. Quand deux mots se rencontrent

Pour comparer les mots, on change de point de vue. On construit d’abord une matrice binaire D : chaque ligne est un document, chaque colonne un mot. Une case vaut 1 si le mot apparaît au moins une fois. Sélectionne une paire pour suivre son calcul.

UNE CO-OCCURRENCE = PRÉSENCE DANS LE MÊME DOCUMENT

La case W[i,j] additionne les produits des colonnes i et j de D. Ainsi W = DᵀD compte les documents qui contiennent les deux mots. Sur la diagonale, W[i,i] compte les documents contenant le mot i. Ici le contexte est le document entier, pas une fenêtre de quelques mots.

vectorizer = CountVectorizer(binary=True, dtype=np.int64)
D = vectorizer.fit_transform(train["text"])
W = (D.T @ D).tocsr()

Avec CountVectorizer par défaut : minuscules, tokens d’au moins deux caractères selon l’expression régulière par défaut, pas de lemmatisation automatique. Ce découpage peut différer de spaCy. Le produit peut déborder en int8 : utiliser un entier assez large avant la multiplication. W peut aussi devenir très volumineuse même en sparse.

5. Comparer des profils

Deux mots peuvent avoir des profils de cooccurrence semblables sans apparaître souvent ensemble. La similarité cosinus compare l’orientation de deux vecteurs : elle vaut 1 pour deux directions identiques, 0 pour des directions perpendiculaires.

TOURNER UN VECTEUR

cos(a,b) = (a · b) / (‖a‖ · ‖b‖)

Dans le TP, chaque ligne de W représente le profil de cooccurrence d’un mot avec tout le vocabulaire. On compare la ligne du mot choisi aux autres, puis on retire le mot lui-même. Attention : forte similarité ne signifie pas synonymie ; mots rares et mots très fréquents peuvent fausser les voisins.

idx = vectorizer.vocabulary_["decoding"]
scores = cosine_similarity(W[idx], W)[0]
indices = [i for i in scores.argsort()[::-1] if i != idx][:10]
voisins = vectorizer.get_feature_names_out()[indices]

6. Apprendre des coordonnées

Une ligne de cooccurrence possède une dimension par mot du vocabulaire et beaucoup de zéros. Un embedding pré-entraîné associe à chaque mot un vecteur généralement dense de taille fixe. Le modèle skip-gram apprend des représentations à partir des contextes des mots.

DEUX REPRÉSENTATIONS, DEUX QUESTIONS

WComptes document × document via DᵀD : une dimension par mot
300Dimensions du modèle NLPL utilisé dans le notebook
cosMême mesure de direction pour comparer les vecteurs

Le notebook compare les voisins de « decoding » dans W et dans des embeddings anglais pré-entraînés sur Wikipédia. Les corpus, le contexte et la méthode changent en même temps : une différence entre listes ne prouve donc pas que l’une des méthodes est meilleure à elle seule. Les dimensions d’un embedding ne portent pas nécessairement une étiquette interprétable.

vecteur = embeddings.vectors[embeddings.key_to_index[mot]]
produits = embeddings.vectors @ vecteur
normes = np.sqrt((embeddings.vectors ** 2).sum(axis=1))
scores = produits / (normes * np.linalg.norm(vecteur))

Vérifier que le mot existe dans le vocabulaire ; éviter une division par une norme nulle. Les données et modèles d’embeddings peuvent occuper beaucoup de mémoire.
