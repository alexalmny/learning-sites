01 / La question

Un arbre peut devenir une liste.

Dans un arbre binaire de recherche, les clés plus petites vont à gauche et les plus grandes à droite. Pour chercher une clé, on élimine donc une moitié de l'arbre à chaque embranchement.

Mais cette intuition suppose que les deux côtés restent à peu près équilibrés. Insérons des nombres croissants dans un arbre ordinaire : chaque nouvelle clé descend tout à droite.

Arbre binaire de rechercheExpérience 01

Avec n clés, ce chemin peut atteindre une hauteur de n − 1. La recherche prend alors un temps linéaire. L'arbre rouge-noir conserve la règle de l'arbre de recherche, mais ajoute des contraintes qui empêchent les branches de trop diverger.

02 / Les invariants

Deux couleurs, quatre contraintes.

La couleur est une information attachée à chaque nœud. Les feuilles NIL représentent les enfants absents ; elles sont noires. Dans le TP, une sentinelle partagée peut représenter toutes ces feuilles.

01 · RacineLa racine est noire.
02 · FeuillesChaque feuille NIL est noire.
03 · RougeUn nœud rouge ne peut pas avoir d'enfant rouge.
04 · CheminsDepuis un nœud, tous les chemins descendants vers NIL contiennent autant de nœuds noirs.

La dernière propriété est la hauteur noire. Sélectionne un chemin : les cases noires indiquent les nœuds comptés. Ici, on compte la racine et la feuille NIL pour illustrer le principe ; d'autres définitions excluent le nœud de départ.

Comparer les cheminsExpérience 02

Puisqu'il ne peut pas y avoir deux rouges consécutifs, un chemin ne peut pas contenir plus de rouges que de noirs à un facteur constant près. Les hauteurs restent donc logarithmiques :

h ≤ 2 log₂(n + 1)

h compte les arêtes ; n est le nombre de nœuds internes. Recherche, insertion et suppression sont en O(log n) dans le pire cas.

03 / Le geste fondamental

Tourner sans perdre l'ordre.

Une rotation modifie localement la forme de l'arbre. Le fils droit de x monte ; x devient son fils gauche. Le sous-arbre intermédiaire β change de parent. Les clés restent dans le même ordre : α < x < β < y < γ.

Rotation gauche autour de xExpérience 03
x : pivoty : fils qui monteβ : sous-arbre déplacé

Avant : y est le fils droit de x. β est le fils gauche de y.

La rotation seule ne change aucune couleur. Elle préserve l'ordre de recherche, mais pas nécessairement toutes les propriétés rouge-noir ; l'algorithme la combine avec des changements de couleur.

Ce qui bouge en C

y = x->d;             // y doit être différent de NIL
x->d = y->g;          // β devient fils droit de x
if (y->g != nil) y->g->p = x;
y->p = x->p;          // raccorder y à l'ancien parent de x
// mettre à jour la racine ou le bon enfant de x->p
y->g = x;
x->p = y;

Le cas racine est essentiel : si x n'a pas de parent réel, la racine doit désormais pointer vers y. La rotation droite est son miroir.

04 / Construire

Insérer, puis réparer.

On commence exactement comme dans un arbre binaire de recherche. Le nouveau nœud est rouge : remplacer une feuille NIL noire par un nœud rouge dont les enfants sont NIL ne change pas le nombre de noirs sur ce chemin.

Mais si son parent est rouge, la règle des deux rouges est violée. L'oncle et la position du nouveau nœud déterminent la réparation. Utilise les exemples, puis avance étape par étape.

Si le parent est noir, l’insertion est terminée. Si le parent est rouge, on distingue les situations suivantes. Les dessins montrent le parent à gauche ; les cas où il est à droite sont symétriques. Un oncle NIL est considéré noir.

1. L’oncle est rouge

La difficulté vient de deux rouges consécutifs. Puisque l’oncle est lui aussi rouge, on peut changer les couleurs des deux branches sans modifier leur nombre de noirs. Le grand-parent devient rouge : une nouvelle violation peut alors apparaître plus haut.

Exemple : insertion de 1Cas 01

2. L’oncle est noir : le triangle

Le nouveau nœud est du côté opposé à son parent : ici, à droite d’un parent situé à gauche du grand-parent. Une rotation sur le parent redresse ce triangle. Elle ne suffit pas à elle seule : on obtient le cas en ligne, traité juste après.

Exemple : insertion de 7Cas 02 → Cas 03

3. L’oncle est noir : la ligne

Le nouveau nœud et son parent sont du même côté. Le parent devient noir, le grand-parent devient rouge, puis une rotation autour du grand-parent remet le parent au-dessus. La hauteur noire est préservée et le conflit rouge-rouge disparaît.

Exemple : insertion de 1Cas 03

Dans ces trois exemples, l’anneau doré indique le nouveau nœud, le bleu son parent initial, le violet son grand-parent initial et le vert son oncle initial. Le disque central indique la couleur rouge ou noire. Les liaisons sont fondues pendant leur changement ; les positions intermédiaires servent à visualiser le mouvement.

05 / Retirer

Supprimer : où est passé le noir ?

La suppression commence comme dans un ABR. Avec deux enfants, on utilise le successeur — le minimum du sous-arbre droit — pour prendre la place du nœud visé. La couleur à surveiller est celle du nœud retiré de sa position initiale, pas forcément celle de la clé demandée.

Si cette couleur était rouge, aucune hauteur noire ne diminue. Si elle était noire, le chemin passant par le remplaçant x peut manquer d'un noir : on décrit ce déficit comme un « noir supplémentaire » porté par x, même si x est NIL.

Dans les exemples suivants, on vient de supprimer une feuille noire. Le cercle x représente la position NIL qui a perdu un noir. Le halo doré indique ce déficit temporaire ; il ne s’agit pas d’une troisième couleur stockée dans le nœud. Dans chaque exemple, x est à gauche : les cas à droite sont symétriques. Les anneaux indiquent les rôles initiaux ; ces rôles peuvent changer après une rotation.
